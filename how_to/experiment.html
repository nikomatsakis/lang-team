The Rust Language Design Team

Start an experimental feature

Adding a new language feature to Rust requires an apporoved RFC. However, especially for larger designs, it is sometimes helpful to start by experimenting with an implementation first, in order to feel out the design space. There are a few ways to do this.

Use a procedural macro

Prototyping your feature with a procedural macro is always the best option, if it works for you. That allows users on stable to play with it and means you can even gain real experience. As a result, RFCs that have been prototyped with a procedural macro are much easier to evaluate, and you are also able to give real experience reports from actual users, which can help make the case for your idea.

Use an experimental feature gate (requires a lang-team second)

For some features, working in a macro is not convenient, and it would be better to implement it in the real compiler. We allow implementation and experimentation language features on master, but only in limited circumstances:

  • You need to have a lang team champion who supports the idea. The champion must be some active member of the language team.
  • You need to open a PR adding an feature gate to the compiler. This feature gate should be marked as experimental so that it warns if people try to use it.
  • You or the champion should create a tracking issue for this feature and mark it as experimental, indicating that an RFC has not yet been written.
  • The champion should initiative an FCP approving the decision to add the feature gate.
    • Approving a new feature gate does not imply support for the feature. It implies only that the lang team thinks it is worth doing the experiment to see what results.
    • Note to lang team members: If you have concerns about the feasibility or wisdom of the feature, the right course of action is usually to allow experimentation to continue, but ensure that your concerns are noted on the tracking issue. This allows the experimentors to try and gather data and address your concern.

In order to be stabilized, a full RFC will be required. The goal of the experimentation period is simply to gain experience and information so that a better RFC can be authored.
